# SohappyPDF API v1

This is the public developer contract. The server implementation is authoritative. The machine-readable copy is `openapi.json` and `GET /api/v1/openapi.json`.

Do not inspect application source to learn the API.

## Getting started

1. Create an API key in the dashboard (`/app/api-keys`).
2. Store it as a secret. It is shown only once.
3. Call `/api/v1` with `Authorization: Bearer YOUR_API_KEY`.
4. Follow the workflow below.

Local development origin:

```
http://localhost:3001
```

Replace that origin with your deployed API host. This document does not invent a production domain.

All public developer paths are prefixed with `/api/v1`.

## Authentication

The only documented programmatic mechanism is an API key:

```http
Authorization: Bearer YOUR_API_KEY
```

```bash
curl http://localhost:3001/api/v1/files \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Rules:

- API keys are secrets.
- Never commit keys.
- Never put keys in URLs or query parameters.
- Never ship keys in browser JavaScript.
- Revoke a compromised key in the dashboard and create a replacement.

The dashboard session cookie can call the same file and conversion routes while you are signed in. That is for the web app. Integrations should use API keys.

API key create, list, and revoke require a dashboard session. They are not part of this public key-authenticated surface.

A missing or invalid key returns `401` with `UNAUTHORIZED`.

## Files

Upload is **presigned**, not multipart through the API.

```
POST /api/v1/files/upload
  → PUT upload.url (direct object storage)
  → POST /api/v1/files/{id}/complete
```

The API never holds the file bytes. The upload URL is temporary. The response includes `expiresInSeconds` (typically 900 seconds).

### Create upload

```bash
curl -X POST http://localhost:3001/api/v1/files/upload \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "filename": "report.pdf",
    "contentType": "application/pdf",
    "size": 2048
  }'
```

`201`:

```json
{
  "file": {
    "id": "11111111-1111-4111-8111-111111111111",
    "filename": "report.pdf",
    "contentType": "application/pdf",
    "size": 2048,
    "status": "pending",
    "createdAt": "2026-08-24T00:00:00.000Z",
    "updatedAt": "2026-08-24T00:00:00.000Z",
    "expiresAt": "2026-08-24T02:00:00.000Z"
  },
  "upload": {
    "url": "https://example.invalid/upload",
    "method": "PUT",
    "headers": {
      "Content-Type": "application/pdf"
    },
    "expiresInSeconds": 900
  }
}
```

Then `PUT` the bytes to `upload.url` with the returned `Content-Type`. Then complete:

```bash
curl -X POST http://localhost:3001/api/v1/files/FILE_ID/complete \
  -H "Authorization: Bearer YOUR_API_KEY"
```

File statuses: `pending`, `uploaded`, `processing`, `completed`, `failed`, `deleted`.

A completed conversion result is another file. Use its `outputFileId` with the download route.

### Get, list, delete

```bash
curl http://localhost:3001/api/v1/files/FILE_ID \
  -H "Authorization: Bearer YOUR_API_KEY"

curl http://localhost:3001/api/v1/files \
  -H "Authorization: Bearer YOUR_API_KEY"

curl -X DELETE http://localhost:3001/api/v1/files/FILE_ID \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Temporary files expire after about two hours.

## Conversions

Conversion work is asynchronous. `POST /api/v1/conversions` creates the record and enqueues a worker job. It returns **201**, not 202.

Statuses: `pending`, `queued`, `processing`, `completed`, `failed`, `cancelled`.

Poll `GET /api/v1/conversions/{id}` about every 2 seconds while the status is `pending`, `queued`, or `processing`. Stop when the status is `completed`, `failed`, or `cancelled`.

### Create

```bash
curl -X POST http://localhost:3001/api/v1/conversions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: unique-client-key" \
  -d '{
    "sourceFileId": "11111111-1111-4111-8111-111111111111",
    "targetFormat": "png",
    "type": "pdf-to-png"
  }'
```

`sourceFileId` and `targetFormat` are required. `type` is optional when the API can infer it.

Implemented types include `pdf-to-word`, `pdf-to-jpg`, `pdf-to-png`, `pdf-to-txt`, `jpg-to-pdf`, `png-to-pdf`, `merge-pdf`, `split-pdf`, and `compress-pdf`.

### Idempotency

`Idempotency-Key` is supported on conversion create (1–128 characters). A replay with the same key and owner returns the original conversion and does not enqueue a second job or consume another conversion credit.

### Status

```bash
curl http://localhost:3001/api/v1/conversions/CONVERSION_ID \
  -H "Authorization: Bearer YOUR_API_KEY"
```

When `status` is `completed`, `outputFileId` is set.

### Cancel

```bash
curl -X POST http://localhost:3001/api/v1/conversions/CONVERSION_ID/cancel \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Cancel is only valid from statuses that allow the transition. Otherwise the API returns `409 CONFLICT`.

## Download

```bash
curl -X POST http://localhost:3001/api/v1/files/OUTPUT_FILE_ID/download \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json
{
  "download": {
    "url": "https://example.invalid/download",
    "expiresInSeconds": 900
  }
}
```

Fetch `download.url` before it expires. Storage keys, bucket names, and cloud credentials are never returned.

## Errors

Every error uses this envelope:

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Authentication required",
    "requestId": "req_example"
  }
}
```

Implemented codes:

| Code | HTTP |
| --- | --- |
| `VALIDATION_ERROR` | 400 |
| `UNAUTHORIZED` | 401 |
| `FORBIDDEN` | 403 |
| `PLAN_LIMIT_REACHED` | 403 |
| `STORAGE_LIMIT_REACHED` | 403 |
| `API_KEY_LIMIT_REACHED` | 403 |
| `NOT_FOUND` | 404 |
| `CONFLICT` | 409 |
| `FILE_TOO_LARGE` | 413 |
| `RATE_LIMITED` | 429 |
| `CONFIGURATION_ERROR` | 500 |
| `INTERNAL_ERROR` | 500 |

Missing files and conversions both use `NOT_FOUND`. There is no separate `FILE_NOT_FOUND` or `CONVERSION_NOT_FOUND` code.

Validation failures use `400`, not `422`.

Responses never include stack traces, database errors, storage internals, or billing-provider errors.

## Rate limits

Authenticated API-key traffic is limited per key and plan. Exceeding the limit returns `429 RATE_LIMITED` with:

- `RateLimit-Limit`
- `RateLimit-Remaining`
- `RateLimit-Reset`
- `Retry-After` when the request is denied

Wait for `Retry-After` seconds (or until `RateLimit-Reset`) and retry. Do not retry in a tight loop.

Default API request budgets from the plan catalog:

- Free: 30 requests / minute
- Pro: 60 requests / minute

## Plans

Limits are enforced on the server from the entitlement catalog. Defaults:

| Limit | Free | Pro |
| --- | --- | --- |
| Conversions / UTC month | 20 | 500 |
| Storage | 500 MB | 10 GB |
| Max file size | 20 MB | 100 MB |
| API keys | 2 | 20 |
| API requests / minute | 30 | 60 |

Both plans include API access. Hitting a quota returns `403` with `PLAN_LIMIT_REACHED` or `STORAGE_LIMIT_REACHED`. Oversized files can return `413 FILE_TOO_LARGE` after entitlement checks.

## Versioning

- Current public version: `/api/v1`
- Additive changes may appear inside v1
- Breaking changes require `/api/v2` (not created)

## Webhooks

Developer webhooks are not available. Conversion clients must poll. This is the extension point for a later notification API.
